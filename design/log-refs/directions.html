Log references: sectors, factions, spice

Three things a log line refers to have no fixed form today. A sector is bold text with nothing behind it. A faction is a bare sigil. Spice is drawn one way in the log and another in the player panel. This page mocks up ways to give each a single form, with a hover that points at the map. Nothing here is built yet. Pick a direction per section, or mix.

The sample lines below are real ones from a Ship & Move report, seen as the Fremen player. Sizes are the app's: a 15px sentence with 20px icons.

Now

Ship & Move report, as built today

Sigil, white disc for a force count, force icon, bold place name, a number drawn on the harvester icon for spice. The place name does nothing on hover. The sigil shows its name only as a browser tooltip.

Player panel header, as built today

Here the spice count sits beside its icon. In the log below it, the count sits on the icon.

1. Sectors

A sector reference is the territory name plus, for territories with more than one sector, which one. Today that reads "Pasty Mesa (North Sector)". All three directions below highlight the referenced sector on the map while hovered, using the same white shape the map already shows under the mouse. A reference to a whole territory lights all of its sectors.

A · Marked name

Bold name, sector as a small label after it. The label is the form the map popover already uses for its title. Quietest. The only hint that it is hoverable is the underline once you are over it.

B · Wedge glyph

A small ring with the sector's wedge filled, before the name. This is a real symbol for "a sector" the way the harvester is for spice: the glyph shows where on the storm wheel the sector is, and the same glyph can appear in prompts and popovers. A whole territory gets the ring with every one of its wedges filled.

C · Place chip

Glyph and name in a pill, matching the faction chip from the design language. Loudest. Reads well when a line names two places, but long names wrap awkwardly in a 460px panel.

On hover

Hovering "Pasty Mesa · North" (any direction)

The reference gets a gold underline and the sector gets the map's hover shape.

Hovering a whole territory, "False Wall South"

Every sector of the territory is lit.

Sector word, three ways

Pasty Mesa (North Sector) as today
Pasty Mesa North label face, like the map popover
Pasty Mesa · North plain, shorter
Pasty Mesa Sector 6 storm number instead of the compass word

The game names sectors by compass word. The storm wheel numbers them 0 to 17, and the number is what decides whether the storm hits. The wedge glyph in B and C shows the number's position without saying it.

2. Factions

A faction reference is the sigil today, with the name only as a browser tooltip. The design language asks for the name beside the sigil everywhere. All three directions get the same hover: every sector holding that faction's forces is tinted in the faction's colour, and a card opens with what you know about them.

A · Sigil only, as today

Nothing changes visually until hover. Cheapest, and keeps lines short. A new player still has to learn six sigils to read the log.

B · Sigil and name

The name follows the sigil as bold text, so the sentence has a subject. "You" for your own faction, in gold. Lines get longer by one word.

C · Faction chip

The chip from the design language. Strongest identity, and the same object as in the lobby and seats. Heavy when a line names three factions.

3. Spice

You asked for "number inside spice" everywhere. The client draws that one way already, in the log: parchment digits on the harvester icon. The design language draws counts differently, as a spice-orange pill with no icon, and that style is defined in the app's CSS but never used. One of these becomes the form.

Harvester with digits, as the log does today

5915120

20, 24, 36, 36. Reads as the spice token on the map. Three digits overflow the icon, which happens for the CHOAM player and the bank. The icon comes from the skin, so a custom skin changes it.

Calls I would make unless you say otherwise

  • Scope is every rendered message, not just the report. One component draws the log, chat, prompts and deal text, so the new forms appear in all of them at once. Splitting it would take a flag per call site.
  • Hover highlights use the map's existing hover layer. A log reference carries the sector's id, and a few lines of script turn the pre-drawn shape on. No Blazor render on mouse move, and it never fights with a selection in progress.
  • A territory reference lights all its sectors; a homeworld or a place off the map lights nothing and only shows the card or tooltip.
  • The faction card replaces the tooltip, opening on hover after the same short delay as card popovers do now.
  • Your own faction reads "You" in gold, as the design language shows, and hovering it still lights your sectors.
  • Plain counts stay white discs. Forces and other numbers keep the disc so only spice is orange.

Questions

  1. Sector direction: A, B or C above, and which sector word (compass, compass in label face, or storm number)?
  2. Faction direction: A, B or C? B and C add the name beside the sigil, which the reskin rules forbade. This work is UX, so I assume that rule no longer applies.
  3. Spice form: harvester with digits, or the orange pill? "Number inside spice icon" reads as the first, but the design language chose the second.
  4. The card's rows: strike or add any? In particular, should forces on Arrakis split into normal and special forces, and should the card show their leaders?
  5. Player name on the card: for a bot I planned to write "bot". For a human, the account name?
