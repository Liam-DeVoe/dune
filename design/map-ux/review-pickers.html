Sidebar review: smaller number picker

The minus / value / plus control in the sidebar was taller than the buttons next to it and wider than the number it holds. It is now 32px tall, which is the height of a secondary button, with every part scaled to match. Colours, hairlines, radius, the parchment flip, and the disabled look are unchanged. The map's pinned-panel stepper is a different control and is not touched. Screenshots are the sidebar column of the local client at 1600x1000, device scale 2.

Calls I made that you should approve or change

  1. The compact variant is 28px tall, scaled from the new default the same way the old one was: 26px buttons at 14px, a 40px input at 16px, a 26px icon cell with a 16px icon. Its only use is the host's bidding time limit. 28px is still comfortable with a mouse, and the input font is at the iOS floor, so I kept it distinct rather than folding it into the default.
  2. The prompt-card override in the stylesheet, which made the picker slightly smaller inside a prompt's action row, would have made it larger than the new default at its old numbers. I scaled it to the compact variant's numbers. No element in the client currently uses the prompt class, so this changes nothing on screen today.
  3. Battle plan: the arrow and the dial total are wrapped in one non-breaking span so a line break never lands between them. That is the only markup change.
  4. Force selection rows (a location name and two pickers in table cells, used by the worm ride and face dancer panels) only got narrower, since the cells size to their content. I did not screenshot them.
  5. The design guide (design/design-language.html) carries the picker's CSS in its own style block; I updated those numbers to match and nothing else.
  6. Fixtures for bidding, battle and revival now live in scripts/fixtures, and scripts/make-fixture.cs can regenerate them, so scripts/ui/shots.py pickers reproduces these shots.
