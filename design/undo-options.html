Undo: pick a moment, not an event

Today you pick an event from a dropdown and read "up to (including)" to work out whether it survives. All three options below have you pick the gap between two events instead, and the UI states what happens in both directions: what's removed and where play picks up.

This fits the engine exactly. Game.Undo(n) keeps events 0 to n−1 and drops the rest, so "the gap before event n" is Undo(n) with no off-by-one. Undo also returns a new game without touching the current one, which is what makes the board preview in B possible.

Option A

Cut line in the log

The undo dialog becomes the game log, oldest at the top and scrolled to now. Hover between any two events and a line appears. Click to drop the cut there.

  • Everything after the cut is struck through, so what's removed and what stays are both visible.
  • The footer says it in words: back to which turn and phase, just before which event.
  • Quick jumps cover the common cases: start of this phase, start of this turn.
  • Cost: small. It replaces the dropdown in UndoComponent and uses the same data.
  • Weakness: you still read text to know the board state. It doesn't show it.

Option B

Scrub the board

Undo opens a timeline under the map. Each phase is a segment and each event is a tick. Dragging the handle back puts the map into preview, showing the board as it was at that moment.

  • You see where you're going, not a sentence describing it. Forces, spice and the storm are all where they'll be.
  • Clicking a segment snaps to the start of that phase. ← → step one event, and ⇧ steps a phase.
  • The removed stretch is hatched, and the banner names the first event that goes.
  • Cost: large. The map has to render a Game other than Client.Game, and replays have to be fast enough to scrub.
  • Weakness: the other players' screens need something too. They'd see a "host is choosing an undo point" notice.

Option C

Checkpoints first

Most undos fix something recent: a misclick, a bot doing the wrong thing, a phase to replay. So the Undo menu item opens a short list of named moments, each with how many events it removes. Exact picking (A or B) is the last row.

  • One click for the common case, with no scrolling and no reading of event numbers.
  • The phrasing is always "before X" or "start of Y", so it's never ambiguous.
  • Picking a checkpoint shows a short confirm that lists exactly what will be undone.
  • Cost: small. The checkpoints come from Moments and each event's initiator.
  • Weakness: it doesn't stand alone. It pairs with A or B.
