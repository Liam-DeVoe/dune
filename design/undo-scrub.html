How it behaves

  • Choosing Undo in the host menu opens the Undo panel and the timeline under the map. Nothing else about the screen changes.
  • While you scrub, the board, your shield and the report all show the game as it was at that moment. Moving back removes report lines one by one. The report follows the latest phase, as it does in play, and its arrows still step through earlier phases.
  • The handle sits between two events. Hovering the track shows that gap: the event above the gold line stays, the one below is undone.
  • The top strip is the whole game, one block per turn. The track below it is one turn in detail. Click a turn to zoom to it.
  • The Undo panel lists what will be undone, newest first. Hovering an entry lights its tick on the timeline.
  • Esc cancels and puts everything back to now. There are no other shortcuts.
  • Undoing shows today's "Recently undone" card, so a wrong undo is one click to reverse.

What building it takes

  • Preview game. Game.Undo(n) already returns a new game without touching the live one. While undo is open, the client would hand that game to the components that read Client.Game: the board, the player panel and the report. None of them need new UI.
  • Replay speed. Each preview replays history from the start. I haven't measured how long that takes on a long game. If it's too slow to scrub, the client can keep a snapshot at the start of each phase, show that one while dragging, and replay the exact gap when the handle stops.
  • Timeline data. The phases and events come from Game.Moments and History, the same data today's dropdown uses. The same event types stay hidden.
  • Other players. The "host is choosing" notice needs a new hub message. That's optional for a first version, because nothing changes for others until the host confirms.
  • Confirming calls the existing RequestUndo(n) with the gap index. Nothing changes on the server.
