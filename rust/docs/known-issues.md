# Known open issues

Differences between the Rust engine and C# that are already known and assigned. Reviewers: don't report these again, but do report any new instance of one of these classes that isn't listed under it.

- **Rock Melter bot logs a message during deliberation (closed 2026-11-11, needs `--bots check`).** The C# bot's `DetermineRockWasMelted` runs `Battle.DetermineBattleOutcome` on the live plans, which can log "<mirror weapon> becomes a <card>" (and, with a Diplomat, set `CardUsedByDiplomat`) while the bot deliberates. A replay that doesn't run the bots can't produce that change, so it reports a false `hash differs after RockWasMelted` (or after whatever event the fuzzer submitted instead, often a rejected `DealAccepted`), with `Game.ReportList[].Messages.length` among the fields. This happens in about one fuzz game in 1000. It's not an engine bug: the Rust bots make the same change, and `differ --bots check` runs them on fuzz traces too ([differ.md](differ.md#checking-bot-decisions)). Fuzz seed 102 game 193, seed 109 game 40, seed 110 game 151 and seed 116 game 23 all match with `--bots check`. To confirm a new case, rerun it with `--bots check`, or regenerate it with the oracle's `--check-bot-purity true` and look for `botMutatedBy` on the failing line. Fuzz runs without `--bots check` will keep showing it.
