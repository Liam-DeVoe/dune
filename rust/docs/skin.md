# The skin crate

`rust/skin` (`treachery-skin`) is the port of `Shared/Model/Skin.cs` and `Shared/DefaultSkin.cs`: how messages, game objects and enums become text, plus the skin's art references, HTML popups, faction rules sheets and its JSON form. The server (`server/src/render.rs`: error texts and mails) and the view layer (log and status text) use it. Read [PORTING.md](../../PORTING.md) and [engine-conventions.md](engine-conventions.md) first.

## Layout

| Rust | C# |
|---|---|
| `src/skin.rs` | `Skin.cs`, regions Attributes, Descriptions and NamesAndImages, plus the rendering half of `Message`/`MessagePart` (`ToString(IDescriber)`) |
| `src/faction_manual.rs` | `Skin.cs`, region FactionManual (`GetFactionInfo_HTML`, `GetFactionSheet`, the twelve templates) |
| `src/skin_json.rs` | `Skin.cs`, region LoadingAndSaving (`Load`, `Fix`, `SkinToString`) |
| `src/default_skin.rs` | `DefaultSkin.cs`. Generated by `tools/gen_default_skin.py` from `tests/golden/default_skin.json`, which is the C# `DefaultSkin.Default.SkinToString()`. Don't edit it by hand |
| `src/text.rs` | `WebUtility.HtmlEncode` and the regular expression of `WithSpiceIcons` |
| `dotnet-compat/src/fmt.rs` `string_format` | `string.Format` (composite formatting, .NET 10 parser) |

`treachery_skin::default_skin()` is `DefaultSkin.Default`, built once per process.

## Using it

```rust
use treachery_skin::{args, default_skin};
let skin = default_skin();
skin.message_to_string(&message);                        // message.ToString(DefaultSkin.Default)
skin.message_to_string_with_default_describer(&message); // message.ToString() on the C# server: "...*"
skin.describe(&ExpressionElement::from(Faction::Atreides)); // Describe(object)
skin.describe_faction(Faction::Atreides);                   // Describe(Faction)
skin.format("{0} pays {1}", &args![Faction::Emperor, 3]);    // Format(m, params object[])
```

Overloads of one C# name get the parameter type appended, as in the engine: `Describe(Rule)` is `describe_rule`, `GetPopup(TerrorType)` is `get_popup_terror_type`. Optional C# parameters are explicit (`with_spice_icons(text, 18, true)`).

**Live collections.** A C# message holds some game collections by reference (hazards.md 4.5), so it renders their contents at render time. The `_in` variants (`describe_in`, `format_in`, `message_to_string_in`) take the game to read them from. Without a game they print the snapshot the engine took when the message was built, which is the same thing for a message rendered right after it was made (everything the server renders).

**Exceptions.** `Describe` panics where C# throws (a resource card without a location, a skin missing a label that an indexer reads). Neither happens with the default skin in a valid game, so `Format` doesn't catch these panics. It still returns the template unchanged when `string.Format` fails. `Skin::load` returns an error instead of panicking.

## Known differences

- An `Exception` element prints as `Exception.ToString()` without the stack trace (the engine has none). C# appends the trace. Only "Game Error" messages contain one.
- Everything assumes the invariant culture, as the oracle and the server harness do (hazards.md 11.2). Under en-US with ICU, C# would print infinity as `∞`.
- `\b`, `\w` and `\d` of `WithSpiceIcons` and `ToUpper` of the sheet titles use Rust's Unicode tables, which differ from .NET's outside the ASCII and Latin-1 text the default skin holds.
- `Skin::load`'s JSON errors carry serde's messages, not .NET's. Malformed JSON that System.Text.Json reads differently (duplicate property names, comments, numbers in strings) is not covered.

## Differential tests

All three compare with C# byte for byte. The C# side is `skin/csharp-ref` (references `Shared` and the oracle's `StepExecutor.cs`; uses reflection only, no C# hooks).

| Test | Golden | What |
|---|---|---|
| `tests/static_corpus.rs` | `static.jsonl.gz` | Every Describe/Format/GetImageUrl/GetPopup overload on every value of every public enum (plus -1 and 12345), every location, territory, leader, the Messiah, every treachery and resource card, numbers and other boxed values, `GetCenter` of attached locations, `WithSpiceIcons` edge cases, and 4,000 random `string.Format` templates |
| `tests/trace_corpus.rs` | `traces/*.skin.jsonl.gz` | Replays `rust/traces/sample` and renders every validation result, `GetMessage`/`GetShortMessage` of every event, every report message, the `GameStatus` texts of status queries, and at the end every faction sheet and leader popup |
| `tests/skin_json.rs` | `default_skin.json`, `load.jsonl.gz` | `SkinToString` of the default skin, and `Load` + `Fix` on edited skins |

Regenerate the goldens after a C# change (from `rust/skin/csharp-ref`, with .NET 10 on the path):

```sh
dotnet build -c Release
dotnet bin/Release/net10.0/SkinRef.dll skin-json ../tests/golden/default_skin.json
python3 ../tools/gen_default_skin.py
dotnet bin/Release/net10.0/SkinRef.dll static ../tests/golden/static.jsonl.gz
dotnet bin/Release/net10.0/SkinRef.dll load ../tests/golden/load.jsonl.gz
../../tools/heavy.sh dotnet bin/Release/net10.0/SkinRef.dll traces ../../traces/sample ../tests/golden/traces
```

To check a fresh corpus (bots or fuzz traces from the oracle, with `--status every` so status texts are covered):

```sh
O=../treachery-online/Oracle/bin/Release/net10.0/Treachery.Oracle.dll   # from rust/
tools/heavy.sh dotnet $O fuzz --seed 9001 --games 40 --out /tmp/t --dump none --hash none --threads 3 --gzip true --status every
tools/heavy.sh dotnet skin/csharp-ref/bin/Release/net10.0/SkinRef.dll traces /tmp/t /tmp/t-rendered
SKIN_TRACES=/tmp/t SKIN_RENDERED=/tmp/t-rendered cargo test --release -p treachery-skin --test trace_corpus -- --ignored
rm -rf /tmp/t /tmp/t-rendered
```

A call added to the static probe fails `static_corpus.rs` until the test handles it, so new overloads can't go unchecked silently.
